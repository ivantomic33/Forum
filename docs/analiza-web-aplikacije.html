Analiza kompletne web aplikacije i predlozi šta još treba dodati

Pregled trenutnog stanja sistema (frontend, backend, baza, sigurnost, QA) i lista konkretnih preporuka za dalji razvoj, poredanih po prioritetu.

Datum analize: 25.10.2026. · Verzija aplikacije: ~2.7.2 · React 19 + TypeScript + Vite · Express + Supabase (PostgreSQL)

2. Šta NEDOSTAJE — predlozi po prioritetu

Prioritet 1 (visok uticaj, očekivano za produkciju)

Predlog Prioritet Obrazloženje
Aktivacija web push-a (VAPID ključevi + web-push paket) P1 Frontend i šema (push_subscriptions) već postoje, ali server nema instaliran web-push paket niti VAPID_* promenljive — push trenutno ne može da pošalje ništa. Najjeftinija „nova“ funkcionalnost: samo env + npm i --prefix server web-push.
Periodična provera cena deal-ova P1 Price alert se okida samo pri kreiranju/izmeni deal-a. Server već ima tajmer infrastrukturu (digest, kampanje, presence sweeper) — dodati dnevni/tični posao koji povlači cene sa prodavnica (Steam API) i zove postojeći notifyPriceWatchers().
RSS / Atom feed (/rss.xml) P1 Postoji sitemap.xml i OG slike, ali nema RSS feeda za članke i deal-ove. Standard za gaming portale, jeftino (server već sastavlja XML za sitemap iz istih podataka).
Privatne poruke (DM) / inbox P1 Jedina standardna društvena funkcionalnost koja potpuno nedostaje: korisnici se mogu blokirati, pratiti teme, ali ne mogu da razmenjuju poruke. Realtime sloj (Supabase Broadcast) već postoji i može se iskoristiti.
Praćenje korisnika (follow) P1 Postoji „prati temu“, ali ne „prati korisnika“ (feed novih tema od autora koje pratiš + notifikacija). Komplementarno DM-ovima i leaderboardu.

Prioritet 2 (iskustvo i sadržaj)

Predlog Prioritet Obrazloženje
Editovanje teme/odgovora u UI-ju P2 Backend rute PUT /api/forum/threads/:id i /replies/:id postoje, kao i api.updateThread/updateReply klijent metode — ali ih nijedna komponenta ne koristi. Korisnik ne može da izmeni svoj post iz interfejsa. Samo povesti UI na postojeći API.
Respone draft tema / autosave editora P2 Članci imaju draft status (admin), ali običan korisnik gubi dugi tekst teme ako zatvori tab. Autosave u localStorage (već se koristi za bookmarks) ili draft tabela.
Lightbox za slike u člancima/temama P2 Postoji CropModal za upload, ali galerija (MediaGallery) nema zoom/lightbox prikaz.
Kalendar gaming izdanja / događaja P2 IGDB katalog već ima releaseDate — „Najave koje dolaze“ i najava esport događaja su prirodno proširenje Games stranice.
Wiki / baza znanja po igri (guides) P2 Game Page postoji; dodati sekciju „Vodiči“ vezanu za igru (community sadržaj sa glasovima), što povećava SEO dubinu.
i18n proširenje na ceo sajt P2 i18n skela (sr/en) postoji i testira se, ali useT() koriste samo 4 komponente. Većina UI-a je tvrdo na srpskom.
Thread preview / Istraži link preview P2 Rich editor podržava slike, ali nema ugradbenog YouTube/Spotify/Twitch embeda u temama i člancima ( Whitelist-based oEmbed).

Prioritet 3 (rast, administracija, kvalitet)

Predlog Prioritet Obrazloženje
Analitika za autore/admina P3 views se broje, ali admin dashboard nema grafike (pregledi po danu, top članci, retencija). Lako preko postojećeg /api/admin/stats + Chart.js.
Scheduled objavljivanje članaka P3 Newsletter kampanje i digest već imaju zakazivanje (cron-like timer) — isti šablon za publishedAt članaka.
Nagrada „najbolji odgovor“ P3 Glasovi postoje, ali autor teme ne može da označi rešenje (accepted answer) — velika vrednost za hardware/LFG pomoć.
Automatizovani backup u CI P3 scripts/backup.mjs --verify postoji ali nije u CI pipeline-u (.github/workflows/ci.yml pokreće lint/test/build).
E2E testovi za nove module P3 E2E suite pokriva auth, compose, vote, deals, leaderboard, mobile — fale kolekcije, build planner, pretraga, admin panel.
Storybook / vizuelni QA dizajn sistema P3 UI kit je izdvojen, snimci se prave ručno (scripts/design). Storybook bi ujednačio komponente.
Push za digest i price alert (ne samo inbox notifikacije) P3 Kad se P1 push aktivira, povezati i digest/price alert na push kanal.

3. Tehnički dugovi (ne funkcionalnosti, ali vredi srediti)

  • Mojibake u fajlovima — pojedini fajlovi (npr. server/admin.ts, .env.example, delovi SearchPage.tsx) sadrže dvostruko kodirana srpska slova („Ä‡“ umesto „ć“). Postoji alat: node scripts/qa/fix-mojibake.mjs — pokrenuti i dodati u CI.
  • README.md je arhiva — sam kaže da „nije izvor istine“ i upućuje na nepostojeći README.new.md. Srediti ili napraviti taj fajl.
  • In-memory fallback u produkciji — server ima dobru zaštitu (ne startuje bez Supabase-a u NODE_ENV=production), ali neke stvari (site settings, ankete fallback, prisustvo) i dalje imaju memory režim; proveriti da sva upozorenja idu u Sentry.
  • Duple/konfliktne sekcije u .env.example — Supabase Storage blok se pojavljuje dva puta; IGDB ključ je commit-ovan u primer fajlu (treba ukloniti realnu vrednost).
  • localStorage bookmark fallback — gosti čuvaju bookmark lokalno; kad se prijave ne sinhronizuje se automatski ka serveru.
  • Version drift — package.json je 1.0.0, a kod je na ~2.7.2; uskladiti i uvesti CHANGELOG.

4. Preporučen redosled rada

  1. Web push aktivacija (VAPID + web-push paket) — dan-dva rada.
  2. Edit teme/odgovora u UI-ju — API postoji, samo frontend.
  3. RSS feed — par sati.
  4. Periodična provera cena + price alert push.
  5. Privatne poruke + praćenje korisnika (veća celina, 1–2 nedelje).
  6. Ostalo po kapacitetu (kalendar izdanja, wiki, analitika, i18n).
Zaključak: Aplikacija je tehnološki veoma zrela — sigurnost (2FA, CSRF, HttpOnly sesije), SEO, realtime, PWA, gamifikacija i testiranje su na visokom nivou, a svi planirani feature-i (F-1…F-14) su implementirani. Najveće praznine su društvene funkcionalnosti (DM, follow), operativne stvari (push bez VAPID-a, cena-periodična provera, RSS) i mali UX rupice (edit posta u UI-ju, lightbox, autosave). Predlozi iz sekcije 2 su sve što razdvaja aplikaciju od „kompletne“ gaming platforme.
